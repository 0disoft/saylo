# 0.1.0-alpha.3 release

On 2026-10-09, publishing the `alpha` tag for the five packages and the install verification were completed. The approved manifest is in [0.1.0-alpha.3.json](0.1.0-alpha.3.json). From "Scope of changes" through "Verification record" below is the record from when the candidate was prepared on 2026-10-09, and the versions and internal dependencies of all five packages were set together to `0.1.0-alpha.3`. The candidate tarballs and `manifest.json` in `.release/npm/` are gitignored local candidates, not approved CI artifacts. The existing `alpha.1` and `alpha.2` publications and approval JSON files are kept.

## Scope of changes

- Raised the five package versions and internal dependencies (`@0disoft/saylo-core`, etc.) to `0.1.0-alpha.3`, and aligned the local copy entries in the root and `examples/sveltekit` lockfiles. Third-party Node engine, peer major, and TypeScript ranges were not raised.
- Added the Vite `requireCompleteTranslations` boolean (default `false`). When `true`, it runs only in a build (`config.command === 'build'`); dev and the default keep the existing partial-translation fallback ([42](../docs/42-complete-translations.md)).
- The check covers non-hidden locale folders, empty folders, and `initialLocale`, and looks at every namespace and messageID in the base locale rather than `initialNamespaces`. Added the `MISSING_MESSAGE` and `MISSING_NAMESPACE` diagnostics to the core type union, and uses the directory's actual spelling for file hints and the canonical value for `locale`.
- A failure stops before typegen, so the existing `generated.d.ts` is not overwritten. Empty strings and omitted arguments are allowed per the existing contract, and the language quality of translated text is not judged.
- `scripts/pack-smoke.mjs` runs `scripts/pack-fixtures/complete-translations.mjs`. With an actual Vite build of an external pack app, it confirms default partial translations pass, strict mode reports missing `hello` and `help` namespaces, existing types are kept, and the build passes after the fix. The check is gated on the option's presence in `vite/dist/types.d.ts`, so `alpha.1` and `alpha.2` registry consumption skips the new option.
- Two recent performance experiments (simple argument collection and the JSON entry visitor) were reverted and are not in the candidate product code ([40](../docs/40-simple-argument-trial.md), [41](../docs/41-json-entry-visitor-trial.md)). No p95 improvement is claimed.

## Verification commands

```sh
npm run release:check -- --version 0.1.0-alpha.3 --tag alpha
npm run check
npm ci
npm --prefix examples/sveltekit ci
npm exec -- node scripts/pack-smoke.mjs --save-release
npm run release:publish -- --version 0.1.0-alpha.3 --tag alpha
actionlint .github/workflows/release.yml
npm exec -- node scripts/pack-sveltekit.mjs
```

Without `--publish`, `release:publish` only checks the artifact versions, SHA-512 values, and publish plan and does not write to the registry. The pack consumption check that `npm run release:pack` runs with the build reused the `check` build and was run as `npm exec -- node scripts/pack-smoke.mjs --save-release`. `pack-sveltekit` runs the external SvelteKit app's SSR and hydration browser checks against the local candidate tarballs.
