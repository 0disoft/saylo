# 0.1.0-alpha.3 릴리스 후보

2026-10-09 다섯 패키지의 `0.1.0-alpha.3` 후보를 준비하고 로컬 검증을 마쳤다. 버전과 워크스페이스 내부 의존을 `0.1.0-alpha.3`로 맞췄다. 후보 준비 기록이며 push·CI 실행·실제 OIDC 교환·npm 게시는 하지 않았다. `.release/npm/`의 후보 tarball과 `manifest.json`은 gitignore 대상 로컬 산출물이고 승인 CI artifact가 아니다. `alpha.1`·`alpha.2` 게시와 승인 JSON은 유지하며 `releases/0.1.0-alpha.3.json`은 만들지 않는다.

## 변경 범위

- 다섯 패키지 버전과 내부 의존(`@0disoft/saylo-core` 등)을 `0.1.0-alpha.3`로 올리고, 루트·`examples/sveltekit` lock의 로컬 복사 항목도 맞췄다. 서드파티 Node engine·peer 메이저·TypeScript 범위는 올리지 않았다.
- Vite `requireCompleteTranslations` boolean(기본 `false`)을 추가했다. `true`이면 build(`config.command === 'build'`)에서만 검사하고 dev·기본값은 기존 부분 번역 fallback을 유지한다([42](../docs/42-complete-translations.md)).
- 검사 대상은 숨김 아닌 로케일 폴더·빈 폴더·`initialLocale`이고, `initialNamespaces`가 아니라 기준 로케일의 모든 namespace·messageID를 본다. 진단 `MISSING_MESSAGE`·`MISSING_NAMESPACE`를 core 타입 union에 추가하고 파일 힌트는 디렉터리 실제 철자, `locale`은 canonical을 쓴다.
- 실패는 typegen 이전에 끝나 기존 `generated.d.ts`를 덮어쓰지 않는다. 빈 문자열·인자 생략은 기존 계약대로 허용하고 번역 문구의 언어 품질은 판별하지 않는다.
- `scripts/pack-smoke.mjs`가 `scripts/pack-fixtures/complete-translations.mjs`를 실행한다. 외부 pack 앱의 실제 Vite 빌드로 기본 부분 번역 통과, strict의 `hello`·`help` namespace 누락 진단, 기존 타입 유지, 수정 후 통과를 확인한다. `vite/dist/types.d.ts` 옵션 존재로 게이트해 `alpha.1`·`alpha.2` registry 소비는 새 옵션을 건너뛴다.
- 최근 성능 실험 두 건(단순 인자 수집·JSON entry 방문)은 되돌렸고 후보 제품 코드에 없다([40](../docs/40-simple-argument-trial.md), [41](../docs/41-json-entry-visitor-trial.md)). p95 개선은 주장하지 않는다.

## 검증 명령

```sh
npm run release:check -- --version 0.1.0-alpha.3 --tag alpha
npm run check
npm ci
npm --prefix examples/sveltekit ci
npm exec -- node scripts/pack-smoke.mjs --save-release
npm run release:publish -- --version 0.1.0-alpha.3 --tag alpha
actionlint .github/workflows/release.yml
npm exec -- node scripts/pack-sveltekit.mjs
```

`release:publish`는 `--publish` 없이 artifact 버전·SHA-512와 게시 계획만 검사하고 registry에 쓰지 않는다. `npm run release:pack`이 빌드와 함께 도는 pack 소비 검사는 `check` 빌드를 재사용해 `npm exec -- node scripts/pack-smoke.mjs --save-release`로 실행했다. `pack-sveltekit`은 로컬 후보 tarball로 외부 SvelteKit 앱 SSR·hydration 브라우저 검사를 한다.

## 상태와 다음 단계

- registry `alpha` tag는 다섯 패키지 모두 `0.1.0-alpha.2`이고 `0.1.0-alpha.3`은 아직 없다(2026-10-09 확인). `latest`는 placeholder `0.0.0-stage`다.
- `release.yml` `version` 기본값을 `0.1.0-alpha.3`으로 바꿨고 `publish`·`verify_oidc` 기본값은 `false` 그대로다.
- `examples/npm`은 registry `alpha.2` lock을 유지하고 루트 `verify:registry`(`alpha.1`)·`verify:registry:alpha2`·`verify:registry:sveltekit`(`alpha.2`) 명령도 그대로 둔다. 새 버전 registry 검증은 향후 CI 승인 manifest 뒤에 추가한다.
- 새 성능 benchmark는 없다.
- 다음 단계는 검증된 커밋을 묶어 푸시한 뒤 `version 0.1.0-alpha.3`·dist-tag `alpha`로 release workflow를 dispatch하는 것이다. 게시 뒤 승인 artifact로 `releases/0.1.0-alpha.3.json`과 registry 검증을 추가한다. 이 문서는 게시를 수행한 기록이 아니다.
