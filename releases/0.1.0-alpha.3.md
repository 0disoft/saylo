# 0.1.0-alpha.3 릴리스

2026-10-09 다섯 패키지의 `alpha` 게시와 설치 검증을 완료했다. 승인 manifest는 [0.1.0-alpha.3.json](0.1.0-alpha.3.json)에 있다. 아래 "변경 범위"부터 "검증 기록"까지는 2026-10-09 후보 준비 당시 기록이고, 다섯 패키지의 버전과 내부 의존성을 함께 `0.1.0-alpha.3`으로 맞췄다. `.release/npm/`의 후보 tarball과 `manifest.json`은 gitignore 대상 로컬 후보이며 승인 CI artifact가 아니다. 기존 `alpha.1`·`alpha.2` 게시와 승인 JSON은 유지한다.

## 변경 범위

- 다섯 패키지 버전과 내부 의존(`@0disoft/saylo-core` 등)을 `0.1.0-alpha.3`로 올리고, 루트·`examples/sveltekit` lock의 로컬 복사 항목도 맞췄다. 서드파티 Node engine·peer 메이저·TypeScript 범위는 올리지 않았다.
- Vite `requireCompleteTranslations` boolean(기본 `false`)을 추가했다. `true`이면 build(`config.command === 'build'`)에서만 검사하고 dev·기본값은 기존 부분 번역 fallback을 유지한다([42](../docs/42-complete-translations.md)).
- 검사 대상은 숨김 아닌 로케일 폴더·빈 폴더·`initialLocale`이고, `initialNamespaces`가 아니라 기준 로케일의 모든 namespace·messageID를 본다. 진단 `MISSING_MESSAGE`·`MISSING_NAMESPACE`를 core 타입 union에 추가하고 파일 힌트는 디렉터리 실제 철자, `locale`은 canonical을 쓴다.
- 실패는 typegen 이전에 끝나 기존 `generated.d.ts`를 덮어쓰지 않는다. 빈 문자열·인자 생략은 기존 계약대로 허용하고 번역 문구의 언어 품질은 판별하지 않는다.
- `scripts/pack-smoke.mjs`가 `scripts/pack-fixtures/complete-translations.mjs`를 실행한다. 외부 pack 앱의 실제 Vite 빌드로 기본 부분 번역 통과, strict의 `hello`·`help` namespace 누락 진단, 기존 타입 유지, 수정 후 통과를 확인한다. `vite/dist/types.d.ts` 옵션 존재로 게이트해 `alpha.1`·`alpha.2` registry 소비는 새 옵션을 건너뛴다.
- 최근 성능 실험 두 건(단순 인자 수집·JSON entry 방문)은 되돌렸고 후보 제품 코드에 없다([40](../docs/40-simple-argument-trial.md), [41](../docs/41-json-entry-visitor-trial.md)). p95 개선은 주장하지 않는다.

## 검증 명령

```sh
npm run release:check -- --version 0.1.0-alpha.3 --tag alpha
npm run check
npm ci
npm --prefix examples/sveltekit ci
npm exec -- node scripts/pack-smoke.mjs --save-release
npm run release:publish -- --version 0.1.0-alpha.3 --tag alpha
actionlint .github/workflows/release.yml
npm exec -- node scripts/pack-sveltekit.mjs
```

`release:publish`는 `--publish` 없이 artifact 버전·SHA-512와 게시 계획만 검사하고 registry에 쓰지 않는다. `npm run release:pack`이 빌드와 함께 도는 pack 소비 검사는 `check` 빌드를 재사용해 `npm exec -- node scripts/pack-smoke.mjs --save-release`로 실행했다. `pack-sveltekit`은 로컬 후보 tarball로 외부 SvelteKit 앱 SSR·hydration 브라우저 검사를 한다.

## 게시

- [CI run 37935637066](https://github.com/0disoft/saylo/actions/runs/37935637066)은 `main` `534a912`, `publish=true`, `verify_oidc=true`로 실행했다. Node 24.21.0·npm 11·Ubuntu에서 다섯 Trusted Publisher 인증, 185개 테스트(core 75·react 9·svelte 5·typegen 8·vite 83·릴리스 helper 5, fail 0)와 소비 타입 검사, pack 검증, 게시 dry run, artifact 업로드, 실제 게시를 통과했다. 릴리스 작업은 22:16:13~22:17:35 KST에 1분 22초로 끝났고 다섯 패키지를 모두 게시했으며 skip은 없었다.
- 공개 registry에서 다섯 패키지의 `0.1.0-alpha.3` 버전과 dist-tag `alpha`, CI metadata·다운로드 tarball SHA-512 일치를 확인했다. `latest`는 placeholder `0.0.0-stage` 그대로다.
- 게시 직후 공개 metadata는 `alpha.2`를 가리키고 `alpha.3` 버전 endpoint는 404였으나, 재게시 없이 조회·다운로드 가능해졌다. 원인은 확정하지 않는다.
- CI artifact의 manifest를 [0.1.0-alpha.3.json](0.1.0-alpha.3.json)에 기록했다.

## 소비 검증

- `npm run verify:registry:alpha3`: 승인 integrity와 실제 tarball 외부 설치, README 예제, JS/checkJs·TS, typegen CLI, core runtime·React/Svelte SSR, public subpath, Vite lazy build와 parser 제거, 새 완역 fixture(기본 fallback·키/namespace 누락 진단·기존 타입 유지·수정 후 빌드)의 JS/TS 소비를 exit 0으로 통과했다.
- `npm run verify:registry:sveltekit:alpha3`: 같은 승인 registry 파일로 SvelteKit 앱을 설치해 타입 진단 0 errors·0 warnings, client/SSR 빌드, 요청별 ko/en SSR·boot와 canonical/base fallback, dev 연결 수명(listener 정리·idempotent stop·late connection 취소), Node 운영 HTTP, HeadlessChrome 154의 hydration·ko/en/ko 전환·공통 layout 입력/모달 유지·종료/재진입을 통과했다.
- 임시 앱·서버·브라우저는 finally에서 정리했다. 기존 `alpha.1`·`alpha.2` 검증은 이번에 반복하지 않았다. 새 성능 측정과 `examples/npm` lock 변경은 없다. 기존 `verify:registry`(`alpha.1`)·`verify:registry:alpha2`·`verify:registry:sveltekit`(`alpha.2`) 명령은 그대로 둔다.
