# 0.1.0-alpha.4 릴리스

2026-10-11 다섯 패키지를 `0.1.0-alpha.4`·dist-tag `alpha`로 게시했다. 내부 의존(`@0disoft/saylo-*`)도 같은 버전이며, 승인 manifest는 [0.1.0-alpha.4.json](0.1.0-alpha.4.json)에 있다. 변경 범위는 게시된 `alpha.3` 기준점 `39acaf8` 이후 selector 추가와 정확성·성능 수정이다. 서드파티 범위(react 19·svelte 5·vite 8·node 24.x·FormatJS 3·intl-messageformat 12)와 루트 devDependencies는 `alpha.3` 그대로다. 승인 JSON은 성공한 CI의 업로드 artifact에서 가져왔으며, 로컬 후보와 구분한다. 기존 릴리스 기록과 승인 JSON은 유지한다.

## 변경 범위

- React `useI18nSelector`를 추가했다. 순수 selection이고 비교는 `Object.is`로 한다. 캐시를 렌더 클로저에 두어 동시 렌더가 서로의 선택을 덮어쓰지 않고, 선택이 실패하면 캐시를 커밋하지 않으므로 같은 실패가 계속 throw된다([43](../docs/43-react-selectors.md)).
- Svelte `selectSvelteStore`·`getI18nSelector`를 추가하고 `getI18n` 컨텍스트 위에서 typed selection을 공유한다. 선택 store는 상위 source 구독을 공유하고 구독자 수로 수명을 관리한다. 초기 선택 실패는 구독을 정리하고 throw하고, 구독 중 실패는 마지막 값을 유지하면서 `onError` 또는 `console.error`로 보고한다([44](../docs/44-svelte-selectors.md)).
- SSR에서 selection이 snapshot에 묶인다. React hydration은 boot에 묶인 `t`, 여러 catalog 버퍼링, 해제 시 DOM·input·state 유지를 검사하고, Svelte는 요청·중첩 컨텍스트 격리와 컴파일 클라이언트의 DOM 상태 유지, 구독 해제를 검사한다.
- typegen 경쟁 상태를 고쳤다. 대체된 뒤 완료된 쓰기도 디스크를 반영하므로 success key를 기록하고, Vite는 대기 중 typegen 요청을 합쳐 마지막 요청 schema를 복원한다([69](../docs/69-thin-layer-typegen.md)).
- Vite 디스크 재확인을 추가했다. 첫 게시는 즉시 하고, watcher가 억제한 두 번째 저장을 10·30·60ms의 metadata 확인으로 잡는다. `reset`은 이전 타이머를 정리하고 `stop` 이후 완료는 타이머를 다시 설치하지 않는다([75](../docs/75-early-disk-rechecks.md), `08b1d7c`·`eb66af8`).
- live registry는 턴당 한 번 읽고 배치한다. 대체된 read가 파싱한 catalog를 다음 read의 입력으로 넘기고, update reader의 ENOENT는 디스크가 정착한 뒤 삭제로 확정한다. 기준 namespace schema가 없으면 throw 대신 진단을 남기고 파일을 유지해 다음 저장 없이도 활성화한다. 오류 시에도 마지막 정상 catalog와 진단을 게시한다.
- core는 parser 소유 map만 `freezeOwnedMessageMap`으로 깊은 불변 처리하고, 같은 소스·컨텍스트면 성공 parse 결과를 그대로 재사용한다. JSON leaf 편집은 위치 offset으로 단일 값을 바꾸고 구조·escape 변경은 전체 parser로 넘긴다. plain 인자 계약은 한 parse 안에서 공유한다. 완전 검증 결과 재사용은 라이브러리가 깊은 불변으로 인정한 identity에만 적용하고, 변경 가능한 입력은 재사용하지 않는다([49](../docs/49-owned-message-map-freeze.md), [59](../docs/59-json-leaf-edits.md), [74](../docs/74-immutable-validation-reuse.md)). 코드 생성·포맷팅 분리는 그대로이고 package API 변경은 추가뿐이다.

## 검증 명령

```sh
npm run release:check -- --version 0.1.0-alpha.4 --tag alpha
npm run release:pack
npm run release:publish -- --version 0.1.0-alpha.4 --tag alpha
```

`release:publish`는 `--publish` 없이 artifact 버전·SHA-512와 게시 계획만 검사하고 registry에 쓰지 않는다.

## 성능

- 편집 종단 간 최신 warmed 로컬 측정은 small p95 49.57ms·large 80.25ms(각 50표본), 로케일 목록은 77.46·177.83ms(각 25표본)다([75](../docs/75-early-disk-rechecks.md)).
- warmed 로컬 값이며 모든 OS에서 안정적이라거나 cold·paint·IMF가 더 낫다고 주장하지 않는다.
- 비교용 thin-layer i18next prototype은 private 실험이고 제품 package·게시본에 넣지 않는다. 현행 native + FormatJS 구성을 유지하며 별도 제거 작업은 계획하지 않는다([76](../docs/76-runtime-decision.md)).

## 게시

- [CI run 38088660390](https://github.com/0disoft/saylo/actions/runs/38088660390)은 `main`의 `d26506ff78076b282033895f3966fb97dc86306c`, `publish=true`·`verify_oidc=true`로 성공했다. Node 24.21.0·npm 11·Ubuntu에서 다섯 Trusted Publisher 인증, 전체 검사, pack·dry run·artifact 업로드·OIDC 게시를 통과했다. 다섯 패키지 모두 새로 게시했고 skip은 없다.
- 공개 registry의 다섯 exact version·`alpha` tag와 metadata integrity, CI에서 받은 tarball 및 registry에서 다운로드한 tarball SHA-512가 일치한다. `latest`는 `0.0.0-stage`다. 게시 직후 일부 조회에서 새 버전이 보이지 않았으나 재게시 없이 모두 조회·다운로드 가능해졌다.
- 승인 manifest는 CI artifact `saylo-npm-0.1.0-alpha.4`(ID `11683525740`)에서 옮겼다. registry 관측·소비 검증 근거는 [review/release-alpha4-2026-10-11.json](../review/release-alpha4-2026-10-11.json)에 기록한다.
- SvelteKit 로컬 예제 lock의 네 `file:` 패키지와 내부 의존 metadata도 alpha.4로 맞췄으며 `npm --prefix examples/sveltekit ci --workspaces=false --ignore-scripts --no-audit --no-fund`가 통과했다. 서드파티 lock 항목은 변경하지 않았다.

## 게시본 소비 검증

- `npm run verify:registry:alpha4` exit 0. 승인 SHA-512와 exact registry tarball을 대조하고 외부 JS/checkJs·TS 설치, CLI·typegen·README 예제, runtime 인자 거부·public subpath·React/Svelte selector SSR, Vite production lazy build·완역 거부·수정 후 복구·개발 의존성 제거 후 SSR을 통과했다.
- `npm run verify:registry:sveltekit:alpha4` exit 0. 같은 승인 tarball로 독립 앱을 설치해 svelte-check 0 errors·0 warnings, client/SSR build, 동시 ko/en SSR·boot 일치·canonical/base fallback, listener 정리·idempotent stop·late connection 취소, Node 운영 HTTP, Chromium 154 hydration·ko/en/ko 전환·공통 layout 상태·종료/재진입을 통과했다.
- 로컬 소비 환경은 Windows·Node 24.18.0·Vite 8.3.4다. 임시 앱·서버·브라우저는 스크립트 finally에서 정리했다. 과거 버전 소비와 새 성능 측정은 반복하지 않았다.
