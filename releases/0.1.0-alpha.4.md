# 0.1.0-alpha.4 release

On 2026-10-11, the five packages were published as `0.1.0-alpha.4` with the `alpha` dist-tag. The internal dependencies (`@0disoft/saylo-*`) use the same version, and the approved manifest is in [0.1.0-alpha.4.json](0.1.0-alpha.4.json). The scope of changes is the selector additions and correctness and performance fixes after the published `alpha.3` baseline `39acaf8`. Third-party ranges (react 19, svelte 5, vite 8, node 24.x, FormatJS 3, intl-messageformat 12) and root devDependencies remain as in `alpha.3`. The approval JSON comes from the uploaded artifact of a successful CI run and is kept distinct from local candidates. Existing release records and approval JSON files are kept.

## Scope of changes

- Added React `useI18nSelector`. It is a pure selection and compares with `Object.is`. The cache lives in the render closure so concurrent renders do not overwrite each other's selection, and a failed selection does not commit the cache, so the same failure keeps throwing ([43](../docs/43-react-selectors.md)).
- Added Svelte `selectSvelteStore` and `getI18nSelector`, and shares typed selection over the `getI18n` context. The selected store shares the upstream source subscription and manages its lifetime by subscriber count. An initial selection failure cleans up the subscription and throws; a failure during subscription keeps the last value and reports through `onError` or `console.error` ([44](../docs/44-svelte-selectors.md)).
- In SSR, the selection is bound to the snapshot. React hydration checks the boot-bound `t`, buffering of multiple catalogs, and DOM, input, and state retention on unmount; Svelte checks request and nested context isolation, DOM state retention in the compiled client, and subscription cleanup.
- Fixed a typegen race. Because a write that completes after being superseded also reflects to disk, it records a success key, and Vite coalesces pending typegen requests and restores the last request's schema ([69](../docs/69-thin-layer-typegen.md)).
- Added Vite disk rechecks. The first publish happens immediately, and a second save suppressed by the watcher is caught with metadata checks at 10, 30, and 60 ms. `reset` clears previous timers, and a completion after `stop` does not install a new timer ([75](../docs/75-early-disk-rechecks.md), `08b1d7c`, `eb66af8`).
- Reads the live registry once per turn and batches. A superseded read passes its parsed catalog as the input to the next read, and the update reader confirms ENOENT as a deletion after the disk settles. If the base namespace schema is missing, it records a diagnostic instead of throwing, keeps the file, and activates without the next save. Even on error, it publishes the last valid catalog and a diagnostic.
- core deep-freezes only parser-owned maps through `freezeOwnedMessageMap`, and reuses a successful parse result as-is for the same source and context. JSON leaf edits change a single value by position offset; structure or escape changes go to the full parser. The plain argument contract is shared within one parse. Reuse of fully validated results applies only to identities the library recognizes as deeply immutable, and mutable inputs are not reused ([49](../docs/49-owned-message-map-freeze.md), [59](../docs/59-json-leaf-edits.md), [74](../docs/74-immutable-validation-reuse.md)). The codegen and formatting separation stays the same, and package API changes are additive only.

## Verification commands

```sh
npm run release:check -- --version 0.1.0-alpha.4 --tag alpha
npm run release:pack
npm run release:publish -- --version 0.1.0-alpha.4 --tag alpha
```

Without `--publish`, `release:publish` only checks the artifact versions, SHA-512 values, and publish plan and does not write to the registry.

## Performance

- The latest warmed local end-to-end edit measurement is p95 49.57 ms for small and 80.25 ms for large (50 samples each), and locale listing is 77.46 and 177.83 ms (25 samples each) ([75](../docs/75-early-disk-rechecks.md)).
- These are warmed local values. It does not claim stability on every OS or that cold, paint, or IMF are better.
- The thin-layer i18next prototype used for comparison is a private experiment and is not included in the product packages or published artifacts. The current native + FormatJS setup stays, and no separate removal work is planned ([76](../docs/76-runtime-decision.md)).
