# 0.1.0-alpha.2 release

On 2026-10-09, publishing the `alpha` tag for the five packages and the install verification were completed. The approved manifest is in [0.1.0-alpha.2.json](0.1.0-alpha.2.json). The text below is the record from when the candidate was prepared on 2026-10-08. The versions and internal dependencies of all five packages were set together to `0.1.0-alpha.2`. No npm publish, remote push, or GitHub Actions run was performed. The existing `alpha.1` publication and approval JSON are kept.

## Scope of changes

- Adds `@0disoft/saylo-svelte`. It supports Svelte 5 readable and typed contexts, snapshot-bound translations, subscription lifetime, and SSR/hydration ([38](../docs/38-svelte-adapter.md)).
- Includes the core `/runtime` entry and `freezeCatalogs`, plus Vite's production `astRuntime` path. The ICU parser is removed at the Saylo formatter boundary without aliasing the whole app ([07](../docs/07-decisions.md)).
- Includes simple message parsing and argument schemas, relative position sharing, reuse of frozen immutable catalogs, freeze sharing in the development prebundle, and compact development transfer. Reverted experiments are not included, and no claim is made that the p95 performance target was met ([measurements](../docs/10-performance-measurements.md)).
- Retries transient `EPERM`, `EACCES`, and `EBUSY` errors in a limited way when replacing typegen files on Windows. The existing file is kept on failure ([38](../docs/38-svelte-adapter.md)).
- Provides Svelte and SvelteKit 3 examples in the repository and a real tarball consumption verification. The examples themselves are not published npm packages ([39](../docs/39-sveltekit-example.md)).
- Past registry consumption verification uses the approved manifest's version and integrity together with the published metadata and README. This keeps the existing `alpha.1` verification from breaking because of the current source version or a moved dist-tag.

## Verification commands

```sh
npm run release:check -- --version 0.1.0-alpha.2 --tag alpha
npm run check
npm run release:pack
npm run release:publish -- --version 0.1.0-alpha.2 --tag alpha
npm run verify:pack:sveltekit
npm run verify:registry
```

Without `--publish`, `release:publish` only checks the artifact versions, SHA-512 values, and publish plan. The candidate tarballs and manifests in `.release/npm/` are gitignored and do not represent approved CI publish artifacts. `verify:registry` checks the four existing `alpha.1` published packages.
