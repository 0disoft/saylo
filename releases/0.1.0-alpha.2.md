# 0.1.0-alpha.2 릴리스

2026-10-09 다섯 패키지의 `alpha` 게시와 설치 검증을 완료했다. 승인 manifest는 [0.1.0-alpha.2.json](0.1.0-alpha.2.json)에 있다. 아래는 2026-10-08 후보 준비 당시 기록이다. 다섯 패키지의 버전과 내부 의존성을 함께 `0.1.0-alpha.2`로 맞췄다. npm 게시·원격 푸시·GitHub Actions 실행은 수행하지 않았다. 기존 `alpha.1` 게시와 승인 JSON은 유지한다.

## 변경 범위

- `@0disoft/saylo-svelte`를 추가한다. Svelte 5 readable·typed context·snapshot-bound 번역·구독 수명과 SSR·hydration을 지원한다([38](../docs/38-svelte-adapter.md)).
- core의 `/runtime` 엔트리와 `freezeCatalogs`, Vite의 production `astRuntime` 경로를 포함한다. 앱 전체 alias 없이 Saylo formatter 경계에서 ICU parser를 제거한다([07](../docs/07-decisions.md)).
- 단순 메시지 파싱·인자 스키마와 상대 위치 공유·불변 카탈로그 동결 재사용·개발 prebundle의 freeze 공유·compact 개발 전송을 포함한다. 되돌린 실험은 포함하지 않으며 성능 p95 목표 달성을 주장하지 않는다([측정](../docs/10-performance-measurements.md)).
- Windows typegen 파일 교체에서 일시적인 `EPERM`·`EACCES`·`EBUSY`를 제한적으로 재시도한다. 실패 시 기존 파일을 유지한다([38](../docs/38-svelte-adapter.md)).
- 저장소에 Svelte·SvelteKit 3 예제와 실제 tarball 소비 검증을 제공한다. 예제 자체는 npm 공개 패키지가 아니다([39](../docs/39-sveltekit-example.md)).
- 과거 registry 소비 검증은 승인 manifest의 버전·integrity와 게시된 metadata·README를 사용한다. 현재 소스 버전이나 이동한 dist-tag 때문에 기존 `alpha.1` 검증이 깨지지 않도록 한다.

## 검증 명령

```sh
npm run release:check -- --version 0.1.0-alpha.2 --tag alpha
npm run check
npm run release:pack
npm run release:publish -- --version 0.1.0-alpha.2 --tag alpha
npm run verify:pack:sveltekit
npm run verify:registry
```

`release:publish`는 `--publish` 없이 artifact의 버전·SHA-512와 게시 계획만 검사한다. `.release/npm/`의 후보 tarball과 manifest는 gitignore 대상이며 승인된 CI 게시 artifact를 뜻하지 않는다. `verify:registry`는 기존 네 `alpha.1` 게시 파일을 검사한다.

2026-10-08 Windows·Node 24.18.0에서 다음 검증을 통과했다.

| 검증 | 결과 |
| --- | --- |
| `release:check`, `check` | 다섯 패키지 metadata·워크스페이스 테스트·소비 타입 검사 통과. 과거 tag 이동·잘못된 integrity·미승인 버전 검사도 통과 |
| `release:pack` | 다섯 `alpha.2` tarball의 외부 JS/TS·README·React/Svelte SSR·CLI·Vite lazy build 검증 통과. `.release/npm/`에 후보 저장 |
| `release:publish` dry run | 다섯 저장된 artifact의 버전·SHA-512·게시 계획 검증 통과. registry 쓰기 없음 |
| SvelteKit tarball | 기존 빌드 출력을 재사용해 `npm exec -- node scripts/pack-sveltekit.mjs` 실행. HeadlessChrome 154에서 SSR·hydration·ko/en/ko·공유 layout 입력/모달·종료/재진입 통과. runtime 오류·경고 없음 |
| lockfile | 루트·SvelteKit 예제의 버전/내부 의존 항목 일치. 예제의 새 lockfile로 `npm ci` 통과. 서드파티 의존 그래프 변경 없음 |
| `verify:registry` | 기존 네 `alpha.1` metadata·승인 integrity·다운로드 파일·게시 README·외부 JS/TS 소비 검증 통과 |
| workflow·문서 | `actionlint`, 변경된 Markdown의 로컬 링크와 40KB 크기 제한 검사 통과 |

임시 브라우저·서버·소비 앱은 정리했다. 새 성능 측정과 실제 npm 게시·OIDC 토큰 교환은 이번 로컬 검증에 포함하지 않는다.

## 초기 등록 기록

Svelte 패키지는 2026-10-08 staging에 제출했다(`4cd95172-ad66-4bc1-9cc5-b0fc968b1dee`). 2026-10-09 Trusted Publisher 저장과 목록 조회를 확인했다(`f9181faf-2907-4a6c-9956-520689d25568`, `0disoft/saylo`, `release.yml`, `npm-release`). 이후 stage 목록은 비어 있고, 공개 registry에서 Svelte `alpha.2`와 검증된 후보 tarball의 SHA-512 일치를 확인했다. 이 작업에서 stage approve를 실행하지 않았으므로 승인 경로와 실행 주체는 확인하지 않았다.

당시에는 core·react·typegen·vite의 `alpha.2`가 미게시였다. 이후 같은 CI 릴리스에서 나머지 패키지의 게시와 다섯 OIDC 교환을 확인했다. 절차는 [릴리스 runbook](../docs/09-release.md)을 따른다.

## 최종 게시와 소비 검증

- [CI run 37804205176](https://github.com/0disoft/saylo/actions/runs/37804205176), `main` `c36ff13`: 다섯 OIDC 인증·181개 테스트/타입 검사·pack 소비·artifact 업로드 통과. core·react·typegen·vite 게시, 동일 Svelte artifact skip. 1분 16초 완료.
- 다섯 registry 버전과 `alpha` tag·metadata·다운로드한 tarball이 CI 승인 SHA-512와 일치한다. 일부 게시 파일이 처음에는 404였으며 다운로드 가능 상태를 확인한 뒤 검사했다.
- `npm run verify:registry:alpha2`: 외부 JS/TS·게시 README·runtime/React/Svelte SSR·CLI·Vite lazy build·parser 제거 통과.
- `npm run verify:registry:sveltekit`: 승인 registry 파일을 독립 앱에 설치해 타입 검사 0 errors·0 warnings, client/SSR 빌드·개발 연결 수명·운영 HTTP·HeadlessChrome 154의 hydration·ko/en/ko·공유 입력/모달·종료/재진입 통과.
- 직접 `core@0.1.0-alpha.2`·`svelte@0.1.0-alpha.2`를 registry에서 설치한 Svelte 컴파일 SSR·동기 구독 검증 통과.
- 기존 `npm run verify:registry`의 네 `alpha.1` 소비 검증도 통과했다. 임시 앱·서버·브라우저는 정리했다. 새 성능 측정은 수행하지 않았다.
