The schema is `saylo.support/v1`. Implementation `d7097dc`, contract [support diagnostic report](../docs/support-report.md), acceptance [API](../review/support-report-api-2026-10-11.json) and [example UI](../review/support-report-ui-2026-10-11.json).

- Selection build (includeKeys): passing the `includeKeys` array to the Vite plugin `saylo()` selects the messages to emit at build time by an exact `namespace:messageId` list. Array input is a hand-maintained exact list with no wildcards. ### 3) Batched push and a single release workflow

- Push the promotion commits to `main` in one batch. Bundle the push and publication into one unit to reduce verification rounds and runner use.
- Dispatch `release.yml` once with `version=0.1.0-alpha.5`, `dist_tag=alpha`, `publish=true`, and `verify_oidc=true`. A single job runs in the order `release:check` → `npm ci` → `audit:dependencies` → `check` → `release:pack` → `release:publish` (dry run) → artifact upload → OIDC publish.
- The published tarballs are packed by CI directly from the committed alpha.5 source, and the `saylo-npm-0.1.0-alpha.5` artifact the workflow leaves is that output. Local candidates and local pack tgz files are not publication targets.
- Move the CI artifact manifest to `releases/0.1.0-alpha.5.json` and write `releases/0.1.0-alpha.5.md`. These two files do not exist yet. After creating them, change this document's references to links.
