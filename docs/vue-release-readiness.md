# Vue package release readiness

The Vue 3 adapter is prepared for the shared `0.1.1` release under `latest`, alongside core, React, Svelte, typegen and Vite. Its manifest is publishable, uses Vue major 3 as a peer, and depends on the matching core version. The workspace lockfile carries the same version. This preparation does not publish packages or establish registry availability.

The public package list in `scripts/release-check.mjs` owns release metadata checks, candidate version promotion and source verification, artifact manifests, publication order and package-scoped OIDC checks. Vue participates in all six-package paths. Candidate verification rejects unexpected Vue metadata edits, including restoring `private` or leaving its old version behind.

Run `npm run verify:pack:vue` for focused local readiness. It builds core and Vue, packs both, installs the actual tarballs into an independent app, checks public metadata and JS/TypeScript consumers, and renders concurrent request-local SSR trees and escaped rich text. The full `verify:pack` and registry consumer paths run the same Vue SSR fixture whenever their artifact set contains Vue. Historical four- and five-package approved manifests retain their original package sets and hashes.

The Vite documentation bundle includes the Vue API guide. The local preparation checks cover Vue adapter/rich text tests and consumer types, release metadata and lockfile alignment, candidate source integrity, tarball set/integrity rules, mocked OIDC exchanges, historical approvals, and the independent Vue tarball consumer. Full release CI, actual OIDC exchange and registry acceptance remain publication-stage checks.

Before publishing, configure and verify the Vue npm Trusted Publisher for the repository's existing `npm-release` workflow. Run the release workflow against the final committed source, review all six validated artifacts and their integrity, then explicitly authorize publication. Record the successful CI artifact manifest as a new approved release and verify that exact registry release, including Vue. Local candidate tarballs never replace historical approved manifests. If the target version already exists with different bytes, select a new shared version through the normal candidate process.
