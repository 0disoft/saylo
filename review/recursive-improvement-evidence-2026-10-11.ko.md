**React 빈 카탈로그와 로케일 삭제 복구.** 빈 기준 카탈로그가 허용된 뒤 `UnknownMessageError`가 React 렌더를 벗어나 App이 사라지는 것을 수정 전 브라우저에서 재현했다. 전체 문구를 먼저 계산하고 마지막으로 커밋된 정상 snapshot을 기억하도록 고쳤다. 오류 중에도 정상 snapshot의 번역으로 현재 수량을 다시 계산하며, 처음부터 번역이 없으면 필요한 파일·키를 안내하는 입력 화면을 제공한다. `verify:demo:react:recovery`는 임시 예제와 실제 Chromium에서 로케일 삭제·복원, 빈 기준 카탈로그, 수량 변경, 기준 복구, namespace 삭제·복원의 7단계와 빈 카탈로그 첫 실행·입력·복구의 3단계를 통과했다. 입력 DOM·초안·열린 모달·확인 입력·포커스·생성된 문의 자료가 유지되고 브라우저 오류·경고는 0이었다. 파일 복원 후 수정 안내는 해제됐다. `verify:demo:react` 타입·생산 빌드와 cached 수명 검사 1개도 통과했다. 근거는 `review/react-render-recovery-2026-10-11.json`이다. 원본 카탈로그를 변경하지 않고 검사 서버·브라우저·임시 예제를 정리했다. 다른 프레임워크·게시본·실제 BFCache 채택은 이 검사의 범위 밖이다.

**SvelteKit 빈 카탈로그의 SSR·화면 복구.** 빈 ko/en 카탈로그에서 공통 layout의 `demo:home` 번역이 `UnknownMessageError`로 빠져 HTTP 500과 안내 부재를 재현했다. layout 안에서 전체 문구를 계산하고 메뉴·페이지·입력 화면에 공유하며, 마지막 정상 번역은 해당 layout에만 기억하도록 수정했다. 새 SSR 요청에는 수정 안내가 나오고 이미 열린 화면은 마지막 정상 번역·초안·모달·문의 자료를 유지한다. 로케일 삭제·복원 검사에서 영어 파일 복원 후 URL이 그대로면 layout load가 다시 실행되지 않아 재선택이 끝나지 않는 오류도 재현했다. `goto`의 `refreshAll: true`로 같은 URL에서도 갱신한다. `node scripts/verify-sveltekit-recovery.mjs`가 로케일·namespace 삭제·복원과 오류 중 공유 layout 이동의 7단계, 빈 첫 실행의 hydration·입력·복구 3단계를 통과했다. 정상·빈·복구 카탈로그에서 두 페이지와 ko/en의 동시 SSR 12요청도 HTTP 200·no-store·요청 로케일·페이지 문구 또는 수정 안내를 확인했다. 브라우저 오류·hydration 경고 0, 카탈로그 갱신 중 포커스 유지, 페이지 이동에서도 입력 DOM·초안·모달·자료 유지다. 기본 페이지 이동의 포커스 유지까지 주장하지 않는다. 최종 `npm --prefix examples/sveltekit run build`가 컴포넌트 오류·경고 0과 운영 빌드를 통과하고 `npm run verify:sveltekit`의 기존 SSR·boot·연결 정리 검사도 통과했다. 원본 카탈로그는 수정하지 않았고 임시 예제·서버·브라우저를 정리했다. 근거는 `review/sveltekit-render-recovery-2026-10-11.json`이다. 운영 빌드는 정상 카탈로그 한정이며 시작 안내 코드 블록과 게시본에는 아직 적용하지 않았다.
