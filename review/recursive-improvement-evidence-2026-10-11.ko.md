**연결 종료 표시(`5db3517`, 예제 수정).** 개발 서버 연결 종료 표시가 `5db3517`로 들어갔다. 실브라우저에서 모달을 연 채 개발 서버를 멈추면 페이지와 모달 상태가 `Disconnected. Waiting for the development server; last rendered translations remain visible.`로 바뀌고, 입력(관측 note `Keep this disconnected draft`)·열린 모달·포커스(`dialog-note`)·마지막 정상 `heading`(`Saylo from npm`)이 그대로 유지됐다. 서버를 다시 띄우면 Vite가 전체 페이지를 reload해 `Connected`로 복귀하고 입력과 모달은 초기화됐다. 근거 `review/npm-demo-connection-status-2026-10-11.json`은 수정 전후(`Connected` → `Disconnected...`)와 `verify:demo:npm` 3개 통과, 남은 한계를 기록한다: 재연결 대기 분기는 실제 재시작이 reload라 따로 관측하지 못했고, 내부 snapshot 재시도 횟수와 소진된 resync 상태에는 라이브러리 신호와 UI 처리가 아직 필요하며, 카탈로그 편집은 DOM 상태를 보존하지만 서버 재시작은 초안 영속을 보장하지 않는다. 이 예제 수정은 라이브러리 API를 바꾸지 않았다(12행, 상태 신호 API는 뒤에 `b534b4f`로 추가).

**개발 동기화 상태(`b534b4f`).** `packages/vite/test/sync-state.test.mjs` 8개가 통과하고 `npm run check` exit 0, `npm run typecheck:consumers --workspace vite`(JS 소비자 추가 후) exit 0, `npm run verify:pack`(독립 설치 JS/TS 5패키지) exit 0이다. 상태 콜백 안에서 lazy instance `dispose()`를 부르는 경로(정리 뒤에도 콜백이 돌아 source 참조가 남던 문제)를 cleanup·callback guard로 고쳤고, 회귀에 `idle`·`connecting` disposal 2건을 넣었다. 계약 문서 `docs/dev-sync-state.md`와 `packages/vite/README.md` 동기화 상태 절은 이 로컬 미게시 API를 표시한다. 기록 `review/dev-sync-state-acceptance-2026-10-11.json`(`b8540cb`)이 이 검증을 담는다.

SvelteKit은 영어 JSON 파손 뒤 다른 한국어 파일을 저장해도 영어 진단이 유지되고 영어 파일 복원 때만 해제됨을 확인했다. Svelte `tsc`·`svelte-check`(오류·경고 0)·157모듈 생산 빌드와 SvelteKit 검사·생산 빌드·`verify:ssr`가 통과했다. 근거는 `review/dev-sync-ui-svelte-2026-10-11.json`·`review/dev-sync-ui-sveltekit-2026-10-11.json`이다. **SvelteKit 첫 설치 명령 복구.** npm 12가 lifecycle 환경에 내보낸 `npm_config_allow_scripts`를 하위 설치 CLI 인자로 취급해 `EALLOWSCRIPTS`를 냈다. `scripts/setup-sveltekit.mjs`는 하위 npm의 환경에서 이 항목만 제외하고 `--ignore-scripts`를 유지한다. 전역·사용자 설정 파일은 수정하지 않는다. 수정 후 원래 `npm run setup:sveltekit` 명령이 workspace 빌드와 예제 65패키지 설치를 마치고 exit 0이었다. 근거는 `review/sveltekit-setup-2026-10-11.json`이며 Windows·Node 24.18.0·npm 12.0.2에서만 관측했다.

**문의용 진단 자료(`d7097dc`).** `createSupportReport`·`createSupportRecorder`가 최근 32개 진단 이벤트와 이벤트당 앞 64행만 축약한다. 오류 코드·숫자 출처 별칭·위치 좌표·현재 연결 상태·검사된 환경 버전만 담고, 오류 문구·키·원문 출처·request ID는 제외한다. 원본은 기록 시점에 축약하며 반환 객체는 깊게 동결한다. 실제 ICU 파서 오류의 합성 비밀 문자열 제외·허용 목록 검사·상한과 누락 수·초기화·입력 사후 변경 격리 4검사와 JS/TS consumer 검사, `npm run check`, 독립 tarball JS/TS 소비자(`verify:pack`)가 통과했다. 신규 API 소비 사례도 pack 검사에 포함했다. 문서는 `docs/support-report.md`, 근거는 `review/support-report-api-2026-10-11.json`이다.

**React cached pagehide 수명.** 수정 전 생산 ESM 번들에서 입력·모달·진단 자료를 만든 뒤 `pagehide.persisted=true`를 보내면 root가 해제돼 원래 input 대신 `null`이 나오는 것을 재현했다. 수정 후 `verify:demo:react`는 같은 번들의 두 번 캐시 이탈·복귀에서 DOM 정체성·제어된 입력값·열린 모달·자료 문자열을 유지하고, 수량 입력·실제 lazy 영어 청크 로드·진단 초기화도 작동하며 최종 `persisted=false` 이탈 때만 root가 제거됨을 확인한다(타입·생산 빌드·회귀 1검사 exit 0). jsdom은 모달 API를 최소 모델로 대체하므로 native 포커스 복귀를 주장하지 않는다. 실제 production preview 브라우저도 이탈·뒤로가기를 수행했으나 `pageshow.persisted=false`로 새로 로드해 초안이 초기화됐다. 그 복귀 후 영어 전환은 정상 동작했다. 실제 BFCache 채택은 이 환경에서 확인하지 못했다. 서버·탭은 종료했고 근거는 `review/react-demo-history-lifecycle-2026-10-11.json`이다.
